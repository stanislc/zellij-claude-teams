# Historical audit reproduction sources

These are byte-for-byte sources used for the 2026-09-14 audit. They are archived as `.txt` to distinguish them from the future maintained regression suite. The [manifest](manifest.json) records each original filename, size, and SHA-256. The [audit JSON](../2026-09-14-pr-audit-evidence.json) preserves the observations, including the attached live wrong-tab input result.

| Source | Purpose |
|---|---|
| [probe.py.txt](probe.py.txt) | Real wrapper with fake Zellij, both local Bash versions, command/target/capability probes, and the old hardening harness |
| [live.py.txt](live.py.txt) | Actual Zellij 0.45.1 with an attached disposable PTY and two tabs |
| [live-layout.kdl.txt](live-layout.kdl.txt) | Harmless observer/leader layout, also generated by the live source |

No runtime directory, environment snapshot, copied source tree, or command-state file is archived. The former `/private/tmp/zellij-review-nk81l5p9` directory is not required for this handoff.

These objects are present in the planning repository. In a fresh clone, fetch main and `pull/2/head`, `pull/6/head`, `pull/8/head`; fetch the other review heads when repeating the full PR analysis. Verify the exact hashes above exist with `git cat-file -e HASH^{commit}`. PR heads may have moved: a newer head is not an exact reproduction of the historical snapshot. If an old object is unavailable, report that limitation rather than substituting silently.

Create a fresh short temporary path for every run, then extract immutable snapshots with `git archive HASH | tar -x -C DIRECTORY`. For example, from the repository root:

```bash
review_dir=$(mktemp -d /tmp/shim-audit.XXXXXX)
mkdir "$review_dir/main"
git archive 93ed78831b0745d0cfa3b33ba085298f8855ef93 | tar -x -C "$review_dir/main"
cp docs/superpowers/reviews/2026-09-14-audit-sources/probe.py.txt "$review_dir/probe.py"
cp docs/superpowers/reviews/2026-09-14-audit-sources/live.py.txt "$review_dir/live.py"
```

Create the remaining four directories using their listed hashes before invoking probe.py. Do not run the probe in the working checkout: it writes a copy of #2's harness into the `main/tests` snapshot for comparison.

## Platform assumptions and execution

The historical sources assume macOS arm64, `/bin/bash` 3.2, `/opt/homebrew/bin/bash` 5.3, Homebrew tools on PATH, Python 3, and Zellij 0.45.1. They are not portable CI scripts. Read them and check those executables before running. If adapting interpreter paths or session naming, keep the archive unchanged and record the adaptation plus actual versions in the new result.

Run `python3 "$review_dir/probe.py"` for the wrapper/mock observations. Several probes intentionally demonstrate bugs and print their observed nonzero statuses; the historical probe is not a pass/fail acceptance suite. The separate Bash 5.3 #6 interrupt observation, syntax/ShellCheck checks, and zsh lifecycle checks were recorded additionally in the JSON; probe.py alone does not regenerate every JSON field.

The live source creates its own socket/cache/data directories beneath the fresh root and the historical fixed session name `review-nk84`. Use a fresh root; never redirect its socket directory to an existing user session. Run `python3 "$review_dir/live.py"` only where local PTYs and Zellij IPC are permitted. It starts an attached terminal client, launches two harmless commands through the actual wrapper, records geometry/titles, tests the late marker, closes the first agent, and terminates the test session.

The important historical result is `late_marker_in_original_tab=true` and `late_marker_in_agent=false`. A future fixed implementation should reverse that result while preserving startup/placement/cleanup. An unattached background session cannot establish this focus result and must not be silently substituted.

The script's finalizer closes its test session and reaps the client on its normal guarded path. As a historical probe, it is not hardened for every setup failure before that guard. If setup fails early, inspect only its own socket directory and terminate only its named disposable session, for example `ZELLIJ_SOCKET_DIR="$review_dir/s2" zellij kill-session review-nk84`; confirm the session exists there first. Never use kill-all-sessions or broad process matching.

Retain controlled outputs needed for comparison, then remove only the fresh review directory after its processes/session are gone. Do not copy generated `*.env`/command state into the repository. The maintained test harness specified in the acceptance matrix must have stronger setup/finalizer coverage and deterministic independent cases.
