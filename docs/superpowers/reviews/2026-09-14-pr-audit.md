## Findings

### P1: Late send-keys writes into the wrong tab

Source: `bin/tmux:496-505`, particularly the untargeted `zellij action write-chars` at line 502.

After the wrapper consumes its FIFO, `send-keys -t %1 ... Enter` checks whether the recorded Zellij ID file exists but never reads or uses that ID. It writes into the focused pane and reports success. PR #9 intentionally leaves focus with the user, so this old fallback is now unsafe even when the user has not changed focus since spawning an agent.

**Live reproduction:** Zellij 0.45.1, an attached disposable terminal client, two tabs, and harmless `sleep` processes. Focus stayed in the observer tab while two agents were launched in the leader tab. Sending `REVIEW_LATE_INPUT` to synthetic `%1` returned 0. Targeted screen dumps found the marker in observer pane 0, and not in the agent or leader. This could send a real shell command into an unrelated working directory.

**Resolution:** Prefer capability-probed `write-chars --pane-id <recorded-id>`. For older Zellij, explicitly focus the validated target before writing and propagate either operation's failure. #2/#5 contain the older focus fallback, but should be adapted to preserve #9's no-focus behavior on capable versions.

### P1 in open #6: Ctrl-C never takes the interrupt branch

Source: PR #6 `bin/tmux:421`, `if [ "$***" = true ]; then`.

Argument parsing still sets `sk_send_sigint=true`. `$***` expands positional arguments plus literal asterisks; it is not a reference to a variable named `***`. The existing GitHub review finding is correct and the contributor's rebuttal is not supported by the code.

**Reproduction:** With a tracked, FIFO-less fake pane, Bash 5.3 returns success and issues `write-chars` with only a newline. Bash 3.2 instead exits 1 at the later empty-array expansion, `sk_keys[*]: unbound variable`. Neither reaches the signal code.

**Resolution:** Restore the parsed boolean condition and test interruption of a real child process in an isolated process group, including confirmation that no text write occurs. Do not merge #6 unchanged.

### P2: Empty-session deactivation fails under the documented zsh shell

Source: current `deactivate.sh:12`; the same glob remains at line 32 in #2/#5.

With no `*.pid` files, zsh's default NOMATCH behavior aborts before cleanup and environment restoration. A clean `zsh -f` activation/deactivation test returns 126 and `no matches found`. This predates #8/#9 and is not fixed by the hardening drafts.

**Resolution:** Iterate without an unmatched glob, following the existing `command find` approach in activation. Test both the zero-pane and populated-state cases using actual zsh.

### P2: Respawn argument and failure contracts are incomplete

Source: `bin/tmux:538-552`.

The observed Claude single-string compound command works, including spaces, quoting, and shell operators. Multiple arguments are flattened with `${rp_command[*]}`: `respawn-pane -k -t %1 -- printf %s 'two words'` produces `twowords`, losing the argument boundary. A missing target or missing command returns success without starting anything. Invalid numeric targets and attempts to respawn an already running pane do fail.

This is a limitation of the newly added handler, not evidence that the current Claude single-string startup is broken. The [tmux manual](https://man.openbsd.org/tmux#COMMANDS) distinguishes a single shell-command string from multiple arguments executed directly. Use that distinction when consolidating the serializers; do not use a raw join for all calls or escape an entire shell program as one executable name.

### State hardening remains unfinished across the shell variants

Current bash activation inserts duplicate PATH entries on repeated sourcing, changes the environment before rejecting an unsafe root, derives the session directory directly from the session name, and does not check all directory-creation/permission failures. Current deactivation recursively removes the environment-provided state path without validating containment.

#2/#5 improve several of these paths. They still export before completing validation, use a lexical containment check, retain the zsh empty-glob bug, and remove a session's lock and environment snapshot during fresh activation. Their six tests do not prove concurrent activation or multi-tab lifetime safety.

#7 now checks the root before exporting, fixing its earlier review findings. However, it still uses the older unsanitized state-name format, lacks the hardening root variable and deactivation containment check, and prepends PATH again on every re-source. Merging it after #2/#5 without adaptation would give bash and fish different state paths and cleanup rules for the same session.

Treat lock preservation, failed-activation rollback, state-root validation, and cross-shell state naming as explicit acceptance criteria. Session-wide cleanup currently affects all tracked panes; documentation must not imply independent per-tab teardown unless that behavior is implemented and tested.

## Gaps and limits

- Neither merged PR has a CI check suite, and the repository has no committed test harness or CI workflow on main. The historical Copilot runs are not a project regression suite.
- ShellCheck 0.11.0 returns 1: seven unused-variable warnings and nine informational diagnostics concerning dead helpers, source/execute fallbacks, and `A && B || C`. Most were already present; the added live-agent helper adds another informational SC2015 report.
- #2's harness run unchanged against merged main reports 1 passed and 5 failed. These expose missing hardening behavior and strict-shell assumptions, rather than five regressions caused by #8/#9. Separate direct probes confirm three PATH copies on current activation and one on #2.
- Fish is not installed locally; #7 received source and review-thread analysis, not a live fish test.
- No `claude` executable is available here. The live Zellij tests executed harmless stand-in commands through the actual wrapper. An authenticated, full Agent Teams conversation was not run. Contributor-reported Claude 2.1.260/2.1.268 tests remain contributor evidence.
- Older Zellij versions were simulated at the CLI capability boundary, not installed and exercised end to end. Linux execution remains for CI.
- A detached Zellij session was sufficient for placement but not for testing focused input. The final focus/input result used an attached PTY client. Each disposable session was terminated after testing.
